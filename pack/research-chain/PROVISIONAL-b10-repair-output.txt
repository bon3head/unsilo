# 1. Closure-obligations contract

## B10 closure obligation model

Every emitted UnSilo result MUST be accompanied by a closure package proving that the result's meaning is reproducible under one pinned dependency world.

A valid closure package contains:

```
ClosurePackage {
    closure_id
    query_or_finding_id
    dependency_world_id
    evidence_contract_version
    source_dependencies[]
    schema_dependencies[]
    registry_dependencies[]
    classification_dependencies[]
    temporal_dependencies[]
    composition_dependencies[]
    comparison_dependencies[]
    counterevidence_dependencies[]
    computation_receipt
    replay_requirements
    verification_status
}
```

Allowed lifecycle:

```
BUILDING → SEALED → VERIFIED
```

Invalid transitions:
• BUILDING → VERIFIED
• SEALED → VERIFIED without verification receipt
• VERIFIED with changed dependency world

A failed verification produces:

```
INVALID not VALUE.
```

# 3. Dependency hash contract

The closure package MUST pin one dependency world and hash every dependency class:

```
DependencyWorld {
    world_id
    world_sha256
    source_manifest_sha256
    schema_snapshot_sha256
    registry_snapshot_sha256
    classifier_version_sha256
    temporal_anchor_sha256
    composition_spec_sha256
    comparison_baseline_sha256
    counterevidence_index_sha256
}
```

Stale or missing dependencies:
• A stale dependency (captured_at older than the evidence contract's freshness window) is treated as MISSING for verification.
• A missing dependency fails the closure with reason "incomplete dependency world."
• A waiver is permitted only if: (a) the missing class is identified, (b) the impact on reproducibility is documented, and (c) the repair worker signs the waiver under B10 acceptance criteria.

No waiver may convert an UNVERIFIED claim into a verified one.

# 4. Computation receipt contract

Every closure package MUST include a computation receipt:

```
ComputationReceipt {
    closure_id
    executed_by
    executed_at
    inputs_sha256
    transform_chain_sha256
    outputs_sha256
    witness_attestations[]
}
```

Witness obligations:
• At least one independent witness MUST attest the transform chain.
• The witness attestation MUST bind inputs_sha256, transform_chain_sha256, and outputs_sha256 together.
• A receipt with broken hash linkage is INVALID, not VALUE.

# 5. Counterevidence obligations

Counterevidence MUST be modeled as a first-class dependency class:

```
CounterevidenceIndex {
    index_id
    closure_id
    counterevidence_items[]
    disposition_per_item
    unresolved_count
}
```

For every counterevidence item:
• Record its source, capture time, and evidence class.
• Assign one disposition: ADDRESSED, OUT_OF_SCOPE, or UNRESOLVED.
• UNRESOLVED items MUST remain in the closure package and MUST be counted in unresolved_count.
• A closure package with unresolved_count > 0 CANNOT reach VERIFIED.

The proof-lifecycle contract requires that counterevidence be re-evaluated on every SEALED → VERIFIED transition.

# 6. Reproducibility package

The reproducibility package is the deliverable a third party uses to replay the result:

```
ReproducibilityPackage {
    closure_package
    dependency_world
    computation_receipt
    counterevidence_index
    replay_instructions
    environment_spec
}
```

Replay requirements:
• replay_instructions MUST be ordered and complete.
• environment_spec MUST be pinned compiler, runtime, and library versions.
• The replay MUST be executable without access to ORIGINAL-AUTHORITY materials.
• If replay requires missing state, the package MUST declare it and verification MUST fail with:

```

```
