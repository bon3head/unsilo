## Type/numeric discipline
- STRICT: rigid typing but permits LOSSLESS coercion. Rejection guarantee = only when
  lossless conversion impossible. Correction to lab note: fixture must use
  "not-an-integer", not "123".
- Canonical fields (identity, time, evidence class, counts, money, findings): concrete
  STRICT types; ANY never feeds analytic results.
- Counts = INTEGER only, REAL forbidden. Money = exact INTEGER atomic/minor units.
  Ratios/shares = exact numerator+denominator INTEGER pairs; no REAL ratio may control
  a threshold, evidence class, QN admission, or verdict. Integer division truncates —
  bare division is never authoritative; SQLite AVG() unsuitable (returns float);
  semantic average = exact_sum/exact_count. Lab 0.1+0.2 → 0.30000000000000004 is one
  manifestation of the documented IEEE-754 hazard. Overflow = failure/abstention,
  never approximate continuation.
- NULL ≠ FALSE ≠ QN ≠ UR ≠ domain UNKNOWN. WHERE discards FALSE and NULL alike —
  unacceptable for evidence semantics. Tri-valued interval predicates must return
  TRUE/FALSE/UNKNOWN distinctly; UNKNOWN rows enter the UNKNOWN channel explicitly.
  NULL valid_to ≠ infinity. CHECK(x>0) satisfied by NULL → requiredness and validity
  are separate constraints (DDL must respect; actual DDL deferred).

## Query grain / fanout
- Grain = identity tuple for which exactly one analytic observation is intended.
- Every analytic query declares grain; every join feeding an aggregate must prove
  fanout-safety at that grain OR reduce the many-side to the join grain first.
  Silent grain change = failure. Lab 1×3→3 rows is ordinary Cartesian-derived join
  semantics (SQLite SELECT §2.1), not a defect.
